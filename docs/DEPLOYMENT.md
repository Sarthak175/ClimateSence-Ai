# Deployment guide - GitHub → Render (API) + Vercel (website) + Colab (notebook)

Order matters: **train first** (the API refuses to predict without a trained model), then deploy.

## 0. Train the model in Google Colab (≈10-25 min)
1. Upload `notebooks/ClimateSense_AI_ML_Training.ipynb` to Colab (File → Upload) or open it from GitHub (Colab → File → Open notebook → GitHub tab).
2. **Runtime → Run all.** The notebook downloads real data from Open-Meteo (no API key), trains Linear Regression / SVR / Random Forest, evaluates, explains and exports.
3. The last cell downloads `climatesense_artifacts.zip`. Unzip it **in the repository root**:
   ```
   backend/models/best_model.joblib, model_metrics.json, feature_importance.json,
                   feature_schema.json, training_metadata.json, city_climate_normals.csv, figures/*.png
   data/raw/hourly_raw.csv.gz, dataset_metadata.json      data/processed/*.csv
   ```
4. Open `backend/models/RUNTIME_VERSIONS.txt` and set the same `scikit-learn==X.Y.Z` in `backend/requirements.txt` (pickles are version-sensitive).
5. `python tools/generate_report.py` fills `docs/REPORT.md` with your actual numbers.

## 1. Run locally
```bash
# backend
cd backend
python -m venv .venv && source .venv/bin/activate       # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env     # or export variables; at least DEVICE_TOKEN for the ESP32
uvicorn app.main:app --reload --port 8000                # http://localhost:8000/docs

# frontend (second terminal)
cd frontend
npm install
cp .env.example .env.local        # VITE_API_BASE_URL=http://localhost:8000
npm run dev                       # http://localhost:5173
```
Tests: `cd backend && pip install -r requirements-dev.txt && pytest`.
Docker: `cd backend && docker build -t climatesense-api . && docker run -p 8000:8000 -e DEVICE_TOKEN=secret climatesense-api`.

## 2. Push to a public GitHub repository
```bash
git init && git add . && git commit -m "ClimateSense AI"
git branch -M main
git remote add origin https://github.com/<you>/climatesense-ai.git
git push -u origin main
```
`backend/models/*` **must be committed** (Render builds from the repo). `joblib` files are normally < 50 MB; GitHub's hard limit is 100 MB per file - if the Random Forest is larger, rerun with fewer trees or use Git LFS.
Never commit `.env`; `.gitignore` already excludes it.

## 3. Backend → Render
1. [render.com](https://render.com) → *New → Blueprint* → pick the repo (it reads `render.yaml`). Or *New → Web Service* with: Root directory `backend`, Build `pip install -r requirements.txt`, Start `uvicorn app.main:app --host 0.0.0.0 --port $PORT`, Health check `/api/health`.
2. Environment variables:
   | Key | Value |
   |---|---|
   | `PYTHON_VERSION` | `3.11.9` |
   | `CORS_ORIGINS` | your Vercel URL, e.g. `https://climatesense-ai.vercel.app` (comma-separate several) |
   | `CORS_ORIGIN_REGEX` | optional, e.g. `https://climatesense-ai.*\.vercel\.app` for preview URLs |
   | `DEVICE_TOKEN` | long random secret (generated by the blueprint) - only needed for the ESP32 |
3. After the deploy, open `https://<service>.onrender.com/api/health` → `"model": {"loaded": true}`. If `loaded:false`, the `reason` tells you which file is missing.
4. Free plan notes: the service sleeps after ~15 min idle (first request takes 30-60 s - the UI shows a friendly message), and local files such as sensor readings are lost on redeploy.

## 4. Frontend → Vercel
1. [vercel.com](https://vercel.com) → *Add New → Project* → import the repo.
2. **Root Directory: `frontend`**, framework preset *Vite* (build `npm run build`, output `dist`). `vercel.json` already adds the SPA rewrite.
3. Environment variable: `VITE_API_BASE_URL = https://<service>.onrender.com` (public, not a secret). Deploy.
4. Copy the Vercel URL into Render's `CORS_ORIGINS` and redeploy the API if you had not set it yet.

## 5. Final checks
* `GET /api/health?deep=true` shows Open-Meteo, NOAA and NASA as `reachable`.
* Dashboard shows today's data with an API timestamp; *AI Predictions* shows a model name; *Model Lab* matches the notebook output; *Climate Evidence* shows the latest observation months.
* Optional keep-alive: a free uptime monitor pinging `/api/health` every 10 min reduces cold starts (be considerate of the free tier).

## Troubleshooting
| Symptom | Fix |
|---|---|
| Browser console: CORS error | `CORS_ORIGINS` must contain the exact Vercel origin (scheme + host, no trailing slash) |
| "Model not available" on every page | artifacts not in `backend/models/` in the deployed commit |
| `scikit-learn version differs` warning | pin the version from `RUNTIME_VERSIONS.txt` |
| 502 `upstream_unavailable` | provider outage/rate limit; cached data are used automatically when available |
| 401 from ESP32 | token mismatch between sketch and server |
